# Corpus conventions

These rules come from the user's corrections. Breaking one has cost a release before.

## Look and copy
- Nothing renders under 14px. The one exception is Settings → Text size → Small, and only as the user's explicit choice.
- Dark only until the light Stitch designs exist. Brand:
  - background `#09090B`, gold `#C0A04A` → `#9A7B2C`, gold text `#C9A95A`;
  - Newsreader for display, Manrope for UI;
  - the column width is the `--col` token, never a hard-coded 390px.
- Copy:
  - no em dashes, no middle-dot lists, no ALL-CAPS labels;
  - sentence case, plain verbs;
  - errors say what happened and what to do.
- Judge against native Android conventions, not the web:
  - no system `<select>` or `<datalist>` (use `openPicker`);
  - keep fields clear of the keyboard (`initKeyboardAvoidance`);
  - the pinned top bar sits under the status bar (`--sat`);
  - pull-to-refresh is the disc; results go in the snackbar.
- New icons must be in the subset: run `node scripts/icon-names.mjs --check`, and `npm run fonts` if it reports missing names.

## Files
- `src/screens.css` is generated by the scratchpad `stitch/scope.py` from the approved Stitch HTML, and `web/corpus.css` is built by `npm run build:corpus`. Hand-edit `src/corpus.css` only. Since corpus.css comes before screens.css, override design rules with a more specific selector or `!important`.
- Screen layouts come from the approved Stitch designs. Reuse their classes and `data-s` ids; don't invent a new visual language.
- Fit-to-screen (fixed layout width W: 470/430/390, set in the `index.html` head script) applies on Android only. iPhone keeps device width until it has been tested on a real iPhone.

## Money: one set of numbers
- Every valuation goes through `getInvCurrentValue`, `getInvInvestedCost`, `hasKnownCost`, `isMarketLinked` and `marketBook` in `web/app.js`. `regenWealth.js` calls these through `appData`; never copy the formulas.
- Cost is what was paid, or unknown. It is never today's price, and a statement value is never a cost.
- `amount` is ambiguous across code paths. Don't read it as cost for unit holdings.
- EPF, PPF, FDs, schemes and bonds are balances, not "invested for a gain".
- The AI gets computed figures and is told to quote them, never to do arithmetic.
- Anything touching money gets a fixture test with hand-worked figures in `scripts/verify-money.mjs` or `scripts/verify-links.mjs`, reconciled to the broker to the rupee.

## Identity and linking
- Two records are the same thing only by a strong key: ISIN, scheme code, ticker, or `_sameFund` (plan and option aware). Never a substring test.
- Import matching goes through `_findStatementMatch`, which is one-to-one and never matches a USD holding to an Indian row. Import paths run `migrateHolding` and assign `newId`.
- SIPs link through `_matchHolding`. A deleted holding re-links or unlinks its SIPs through `_relinkSips`.
- After fixing any bug, hunt its whole class before calling it done.

## Profile and AI
- Profile v2: every answer except name and age is multi-select, and anything about how money is treated is asked per asset class (`PROFILE_CLASSES`, `PROFILE_ASK`). If you add a question, follow the same rule or state why not.
- Every profile field must reach the prompt through `normProfile`, `profileBlock` and `judgeRules`, and a test must assert it. The user's name is never sent.

## Process
- Run `npm run verify` before shipping, and ship with the `ship-corpus` skill.
- Don't commit or push unless asked. Never put anything from `client_work/` into the repo.
