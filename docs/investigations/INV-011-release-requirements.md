# INV-011 — Initial release requirements

Updated: 2026-10-14 (Asia/Calcutta). State: **Queued**. Depends on: INV-010 closed. Research owner: Codex; decision owner: product owner. [Tracker](../product-plan.md).

## Decision to establish

The agreed private-prototype requirements and acceptance criteria that permit UI specification and implementation, plus the separate conditions for independent beta and eventual public paid release. The full AI target follows DEC-015; exact supported capabilities must follow evidence, not promises.

## Research questions

- Turn accepted earlier decisions into a feature/coverage list with explicit exclusions, supported platforms and refresh promises. Every connection maps to permitted acquisition, transaction and price capabilities.
- Define a short initial profile, user-selected first question, optional permission explanations and progressive learning/follow-up. Include inspectable/correctable context, import review, duplicates, missing history, stale data, reconnection and recovery; avoid jargon and repetitive questions.
- Specify private owner acceptance for researched AI answers using portfolio, goals, risk, budget and actual spending, with evidence/suitability/risk criteria from INV-008. Validate the target capability only within established permissions; private-first does not waive them. Separate owner acceptance from independent beta demand/payment evidence.
- Establish accessibility and supported-device requirements for eventual broad usability while explicitly defining the first eligible/supported audience; record text scaling, navigation, touch targets and assistive-technology expectations.
- Define reliability/support procedures, quote/transaction freshness, calculation correctness and observability without logging identifying financial records.
- Set private-beta recruitment, activation/retention/value and payment-experiment measures with sample and evaluation windows; distinguish hypotheses from proven metrics.
- Carry DEC-012/PV1 into the release gate: reopen INV-001 when independent beta users become available, define its external evidence/acceptance criteria with INV-009, and require recorded results plus the owner's go/no-go before public launch. Do not substitute founder use for wider validation.
- Carry DEC-014/LR1 into publication readiness: review actual outputs, prompts and marketing against applicable launch-date requirements and resolve classification gaps. G2 must separately evidence provider eligibility. A future closed investigation does not mean either readiness gate passed; INV-002 is currently reopened. Resolve enabling recommendation requirements before building affected behaviour, and review actual outputs before public launch.
- Prepare Play Store publication requirements when relevant, including declared permissions, privacy/data disclosures, build identity, distribution/signing and applicable tests. There is no publication date to optimise against.

## Evidence required

Closed INV-001–INV-010 reports and linked decisions; complete coverage/cost/privacy matrix; triaged bug backlog; owner acceptance of release requirements and beta criteria. Runtime/browser/native verification happens later against the implementation.

## Acceptance scenarios to define

First run, partial imports, duplicate imports, missing cost/history, stale quotes, interrupted sync, revocation, offline use, backup/recovery and calculation edge cases from INV-008. Add multi-owner access only if accepted. Add first goal/portfolio question selection, short onboarding, context correction, purposeful follow-up, research/source failures and budget-constrained suitability cases. No scenario is marked passed from planning documents alone.
